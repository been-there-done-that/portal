# Request Inspector — Design Spec

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Every HTTP request proxied by portal is captured — with full headers and bodies — and viewable in a live Svelte dashboard served at `_.localhost`. New requests appear in real-time via SSE. History persists in SQLite until manually cleared. Zero overhead on the proxy hot path.

**Architecture:** A new `src/inspector/` Rust module runs alongside the daemon. The proxy intercepts each request with a non-blocking `try_send` into a bounded mpsc channel. A background worker drains the channel, writes to SQLite, and broadcasts to SSE clients. An internal axum HTTP server serves the Svelte UI (embedded via `rust-embed`) at `_.localhost`, registered as a normal route in the daemon's route table. The Svelte frontend lives in `ui/` and is built with Vite + shadcn-svelte.

**Tech Stack:** Rust (`axum 0.8`, `rusqlite`, `rust-embed`, `tokio::sync::mpsc/broadcast`), Svelte 5 + shadcn-svelte + Vite (`ui/`).

---

## Zero-Overhead Capture Contract

The proxy hot path **never `.await`s** anything inspector-related. The only work on the critical path is:

1. Clone request/response headers (already in memory)
2. Clone body bytes up to 1 MB cap (O(1) bounded)
3. `channel.try_send(event)` — non-blocking, nanoseconds

If the channel is full (8192 slots), the event is **silently dropped**. A slow SQLite write or a crashed inspector worker can never stall a proxied request.

## Proxy Intercept

### Where

`src/proxy.rs` — in the request handler, after the response is received from the backend and before it is forwarded to the client. A single optional `Arc<InspectorSender>` is threaded through the proxy state.

### CapturedRequest struct

```rust
pub struct CapturedRequest {
    pub id: u64,                    // generated by proxy (atomic counter)
    pub hostname: String,
    pub method: String,
    pub path: String,               // includes query string
    pub req_headers: Vec<(String, String)>,
    pub req_body: CapturedBody,
    pub res_status: u16,
    pub res_headers: Vec<(String, String)>,
    pub res_body: CapturedBody,
    pub duration_ms: u64,
    pub timestamp: i64,             // Unix ms
}

pub enum CapturedBody {
    Full(Bytes),                    // body <= 1 MB
    Truncated { prefix: Bytes, total_bytes: usize }, // body > 1 MB
    Empty,
}
```

### InspectorSender

```rust
pub struct InspectorSender(tokio::sync::mpsc::Sender<CapturedRequest>);

impl InspectorSender {
    /// Non-blocking. Drops event silently if channel is full.
    pub fn send(&self, req: CapturedRequest) {
        let _ = self.0.try_send(req);
    }
}
```

### Body cap

Bodies are read through the existing buffering path. Once both req and res bodies are in memory (already the case for TLS termination), cloning up to `BODY_CAP = 1_048_576` bytes costs one allocation. The original full body is forwarded to the client unchanged.

## Inspector Module — `src/inspector/`

### Files

| File | Responsibility |
|------|---------------|
| `mod.rs` | Module entry point, `Inspector::start()` |
| `db.rs` | SQLite via `rusqlite` — schema, insert, query, delete |
| `sse.rs` | `tokio::sync::broadcast` channel, SSE event formatting |
| `server.rs` | `axum` routes, request handlers |
| `assets.rs` | `rust-embed` — embeds `ui/dist/` at compile time |
| `types.rs` | `CapturedRequest`, `CapturedBody`, JSON serialisation |

### Inspector::start()

```rust
pub struct Inspector {
    sender: InspectorSender,   // given to proxy
}

impl Inspector {
    /// Spawns the background worker + axum server.
    /// Returns the sender half to thread into the proxy.
    pub fn start(db_path: PathBuf, port: u16) -> Inspector
}
```

Called from `daemon/mod.rs` before the proxy starts. The returned `InspectorSender` is stored in proxy state.

### Background worker

Single `tokio::spawn` task:

```
loop {
  recv CapturedRequest from mpsc channel
  db.insert(&req)          // rusqlite, WAL mode
  sse_tx.send(event)       // broadcast to SSE clients, ok to fail
}
```

Writes are individual (not batched) — local dev traffic is low enough that batching adds complexity for no benefit.

### SQLite schema (`db.rs`)

```sql
CREATE TABLE IF NOT EXISTS requests (
    id           INTEGER PRIMARY KEY,
    hostname     TEXT NOT NULL,
    method       TEXT NOT NULL,
    path         TEXT NOT NULL,
    status       INTEGER NOT NULL,
    duration_ms  INTEGER NOT NULL,
    timestamp    INTEGER NOT NULL,     -- Unix ms
    req_headers  TEXT NOT NULL,        -- JSON array of [key, value] pairs
    req_body     BLOB,
    req_truncated INTEGER NOT NULL DEFAULT 0,
    req_total_bytes INTEGER NOT NULL DEFAULT 0,
    res_headers  TEXT NOT NULL,        -- JSON array of [key, value] pairs
    res_body     BLOB,
    res_truncated INTEGER NOT NULL DEFAULT 0,
    res_total_bytes INTEGER NOT NULL DEFAULT 0
);

CREATE INDEX IF NOT EXISTS idx_requests_hostname ON requests(hostname);
CREATE INDEX IF NOT EXISTS idx_requests_timestamp ON requests(timestamp DESC);
```

WAL mode enabled on connection open: `PRAGMA journal_mode=WAL`.

## axum Server (`server.rs`)

Binds on a random free port (same `find_free_port` utility). Port registered with the daemon route table as `_.localhost → <port>` so the existing proxy handles TLS termination and routing with no special cases.

### Routes

```
GET  /                      serve index.html from embedded assets
GET  /assets/*              serve static assets (JS, CSS) from rust-embed
GET  /api/requests          paginated history (query: ?hostname=&limit=&before_id=)
GET  /api/stream            SSE — live feed of new requests
DELETE /api/requests        clear all history
DELETE /api/requests/:id    delete one request
```

### SSE event format

```
event: request
data: {"id":1,"hostname":"myapp.localhost","method":"GET","path":"/api/users","status":200,"duration_ms":42,"timestamp":1712500321000}
```

Body and headers are **not** included in the SSE event — they are large and only needed when a user clicks a row. The UI fetches full detail on demand via `GET /api/requests?id=N` (or the paginated endpoint filtering by id). This keeps the SSE stream lightweight.

### GET /api/requests

Query params:
- `hostname` — filter by route (omit for all)
- `limit` — max rows, default 100, max 500
- `before_id` — pagination cursor (last id from previous page)
- `id` — fetch single request by id (returns array of 1)

Response:
```json
{
  "requests": [{
    "id": 1,
    "hostname": "myapp.localhost",
    "method": "GET",
    "path": "/api/users",
    "status": 200,
    "duration_ms": 42,
    "timestamp": 1712500321000,
    "req_headers": [["content-type", "application/json"]],
    "req_body": "...",
    "req_truncated": false,
    "res_headers": [["content-type", "application/json"]],
    "res_body": "{\"users\":[...]}",
    "res_truncated": false
  }],
  "has_more": false
}
```

Bodies are base64-encoded if not valid UTF-8.

## `_.localhost` Registration

On `Inspector::start()`, after the axum server binds its port, it calls back into the daemon to register the route:

```rust
// In daemon/mod.rs, after inspector starts:
routes.insert(Route {
    hostname: "_.localhost".to_string(),
    port: inspector_port,
    pid: std::process::id(),
    owner_pid: std::process::id(),
    cwd: String::new(),
    created_at: chrono::Utc::now(),
})?;
```

`_.localhost` is excluded from `portal ls` output (filter in `Ls` handler: skip routes where `hostname == "_.localhost"`).

## Dev Mode

When `PORTAL_UI_DEV=1` is set, the axum server proxies all non-`/api/*` requests to `http://localhost:5173` (Vite dev server) instead of serving embedded assets. This enables hot-reload during UI development without recompiling Rust.

```rust
#[cfg(debug_assertions)]
if std::env::var("PORTAL_UI_DEV").is_ok() {
    // reverse-proxy to localhost:5173
}
```

## Frontend — `ui/`

User scaffolds with:
```bash
cd ui && npx sv create . # Svelte 5
npx shadcn-svelte@latest init
```

Build output: `ui/dist/` — Vite configured with `base: "/"` and `build.outDir: "dist"`.

`rust-embed` bakes `ui/dist/` into the binary at compile time:
```rust
#[derive(RustEmbed)]
#[folder = "ui/dist/"]
struct UiAssets;
```

The Svelte app structure:
```
ui/src/
  routes/
    +page.svelte        ← main inspector view
  lib/
    components/
      RequestFeed.svelte
      RequestDetail.svelte
      Sidebar.svelte
    stores/
      requests.ts       ← SSE connection + request store
    api.ts              ← typed fetch wrappers
```

### Layout: sidebar + feed + detail (3-panel)

- **Left sidebar (200px):** route list (clicking filters the feed), method/error filter chips, "Clear history" button
- **Center feed (300px):** request rows — method badge, path, status, duration, time. Clicking a row opens detail. New rows prepend with a subtle fade-in animation via SSE.
- **Right detail panel (flex):** tabs for Request / Response / Headers / Timing. Bodies shown as syntax-highlighted JSON when content-type is JSON, raw text otherwise. Truncated bodies show a notice.

### SSE connection in Svelte

```typescript
// stores/requests.ts
const es = new EventSource('/api/stream');
es.addEventListener('request', (e) => {
  const req = JSON.parse(e.data);
  requests.update(list => [req, ...list].slice(0, 2000)); // cap in-memory
});
```

On mount, `+page.svelte` fetches the last 100 requests from `/api/requests` to populate history, then SSE takes over for live updates.

## `portal inspect` CLI command

Added to `CliCommand` enum:
```rust
/// Open the request inspector in your browser
Inspect,
```

Handler:
```rust
CliCommand::Inspect => {
    let url = "https://_.localhost";
    #[cfg(target_os = "macos")]
    std::process::Command::new("open").arg(url).spawn().ok();
    #[cfg(target_os = "linux")]
    std::process::Command::new("xdg-open").arg(url).spawn().ok();
    println!("Opening {url}");
}
```

## Out of Scope

- Per-route opt-out config flag (v2)
- Retention time limits / auto-expiry (v2)
- Replay requests from the UI
- Binary body pretty-printing (shown as hex dump, not decoded)
- Windows support for `portal inspect` open command
- WebSocket frame capture
